# 9장 LAB · 만족이 높을수록 재방문이 낮다? 요인점수부터 점검하기

교재 마지막에는 만족도가 높을수록 재방문이 낮다는 결과가 나옵니다. 이것을 “고객은 만족하면 떠난다”로 해석하거나, 원하는 양수가 나올 때까지 문항을 지우는 대신 점수를 어떻게 만들었는지부터 살펴봅니다.

## 교재와 연결

[요인분석](https://kwangminpark.github.io/businessAnalytics/Chapter9.html) — 9.2~9.5 PAF·회전·점수, 9.6 한계, 9.7 실제 커피전문점 설문 종합실습

선수학습: 6~8장: 회귀·매개·PCA

권장 시간: 기본 120분 + 심화 40분 (수업 운영에 따라 조절)

## 이번 실습에서 배울 것

- PCA와 공통요인분석을 구별하고 PAF·회전·공통성을 읽는다.
- 요인 이름과 방향을 열 순서 대신 문항 내용으로 정한다.
- 장말의 역방향 계수를 재현한 뒤 가능한 설명을 검토한다.

## 먼저 읽을 데이터

기초 연습은 9.2.4의 공개 생성식(seed 123)을 재현한 200명·9문항 교육자료입니다. 본실습은 교수 제공 ch9_data1.csv의 416행·45열입니다. 성별 코드 1열과 문항 44열이며 본문의 “총 34항목”과 다릅니다. 이 파일은 교재에서 실제 설문으로 소개하지만 조사 시점·표집·정확한 원문항 및 역문항 설명은 파일만으로 확정되지 않습니다. 분위기/접근성/편의성/친절도/맛/가격/메뉴/명성/외만족/내만족/신뢰/재방문 영역을 포함합니다. 일부 값은 1.5 등 소수이므로 정수로 반올림해 응답을 바꾸지 않습니다.

## 준비와 실행

전체 ZIP을 새 폴더에 풀고 report-template.qmd를 엽니다. 문서 안의 번호별 R 청크를 순서대로 실행합니다. 분석 코드와 판단·해석 작성란은 QMD에서 수정합니다. `quarto render report-template.qmd --to html`로 보고서를 생성합니다. 원본 data를 덮어쓰지 않고 계산 결과는 output에 저장됩니다.

`psych`와 `GPArotation`이 필요합니다. 처음 한 번 R에서 `install.packages(c("psych", "GPArotation"))`를 실행하세요. 패키지를 설치하려면 인터넷이 필요합니다. 데이터 분석 자체에는 인터넷이나 AI 접속이 필요하지 않습니다.

## Quarto 학생 분석 보고서

학생용 report-template.qmd와 교수자 예시 reference-report.qmd는 제공된 Quarto 학생 리포트 템플릿을 기반으로 합니다. 첫 페이지는 결론·권고·핵심 근거·실무적 의미·한계, 본문은 질문→자료→번호별 분석→해석→진단·민감도→결론 순서입니다. 학생용에는 해석 작성란, 교수자용에는 실행값을 반영한 예시 해석이 있습니다.

처음 한 번 install.packages(c("knitr", "rmarkdown"))로 패키지를 준비합니다. ZIP을 풀고 같은 폴더에서 `quarto render report-template.qmd --to html`을 실행하면 QMD 안의 번호별 R 청크를 실행해 표·그림을 생성합니다. 분석 코드와 학생 작성란은 QMD에서 수정합니다. 핵심 근거 선택·모형 선택·판단·해석은 학생이 작성하며 첫 페이지도 분석을 마친 뒤 직접 채웁니다. 별도 analysis.R 없이 실행할 수 있습니다. 캐시와 freeze를 사용하지 않습니다. 기본 R 중심의 분석으로 tidyverse와 broom은 필요하지 않습니다.

Word: `quarto render report-template.qmd --to docx`. PDF: `quarto render report-template.qmd --to pdf` (한국어 LaTeX 필요). styles.css·pagebreak.lua·reference.docx는 원본 템플릿 그대로 ZIP에 포함되어 있습니다. QMD 파일만 다운로드하면 이 보조파일과 데이터가 빠지므로 전체 ZIP을 사용하세요.

reference-output은 검산용입니다. 먼저 자신의 output을 만들고 숫자와 표본 수를 대조하세요. 그림의 글꼴·픽셀은 운영체제에 따라 달라질 수 있습니다.

## 기본 실습 1 · 작은 예제로 추출과 회전 익히기

9문항에서 평행분석으로 요인 수를 살피고 세 요인의 PAF를 회전 전/varimax 후 비교합니다. 적재량은 문항과 요인 관계, 공통성은 선택한 요인으로 설명되는 문항 분산입니다. 회전은 새 고객자료를 만드는 과정이 아니라 축을 읽기 쉽게 바꾸는 과정입니다.

## 기본 실습 2 · 실제 설문의 열을 감사

survey-audit.csv에서 열 수·범위·소수값을 확인합니다. 이름으로 문항을 선택합니다. 분석 목적상 역할이 다른 설명영역과 결과영역을 나누되 요인분석으로 인과 방향이 정해지는 것은 아닙니다. 코드의 문항 제외는 교재 결과 재현을 위한 선택입니다. 연구 정답으로 간주하지 말고 어떤 개념을 잃는지 기록하세요.

## 기본 실습 3 · 교재의 장말 결과 재현

교재의 단계별 선택을 stage-iv_27→iv_24→iv_21→survey-iv-loadings(17문항), stage-dv_17→dv_14→dv_10→survey-dv-varimax(7문항) 순서로 비교합니다. 가격·메뉴·신뢰·명성·내만족을 제외하면 어떤 의미를 잃는지 적습니다. 이후 설명 문항 17개의 5요인 점수와 외만족 4문항+재방문 3문항의 varimax 점수로 회귀를 실행합니다. 어떤 열이 만족/재방문인지 적재표로 찾고 평균 문항과 방향을 맞춥니다. PA1을 무조건 만족으로 이름 바꾸지 말고, 음의 만족 계수가 재현되는지 확인합니다. 최초 결과영역 17문항 모형은 재방문2의 공통성이 약 1.018로 1을 넘어 Heywood 경고가 납니다. 이 중간 모형을 정상적인 점수로 채택하지 말고 과도한 요인 수·문항 중복·추출 가정을 점검할 대상으로 표시하세요.

## 기본 실습 4 · 음의 계수의 출처를 좁히기

varimax 점수의 만족-재방문 단순상관과 다른 요인점수를 넣은 조건부 계수를 비교합니다. 이어 같은 7문항에 oblimin 회전과 문항평균을 사용합니다. 회전/점수 정의만 바꿨을 때 관계가 얼마나 달라지는지 읽습니다. 점수 방식이 달라 계수의 절대 크기를 효과 크기처럼 직접 비교하지 말고 방향·상관·구간을 중심으로 봅니다.

## 기본 실습 5 · 전략으로 넘어가기 전 보류할 것

varimax는 요인 간 상관을 0으로 두는 모형입니다. 후속 분석에서 만족과 재방문의 관계를 묻는데 이 구성 방식이 적절한지 논의합니다. 음의 조건부 계수 자체가 입력 오류의 증명은 아닙니다. 억제효과, 점수 구성, 원문항·역코딩, 표본 특성을 확인합니다. 원문항 확인 없이 재방문3을 역문항이라고 임의 반전하지 않습니다.

## 멈추고 해석하기

방법 선택 이유, 결과의 조건·단위, 진단에 따른 판단 변경, 결론의 적용 범위와 한계를 자신의 말로 쓰세요.

## AI와 함께 확인하기

“같은 설문에서 varimax·oblimin·문항평균을 비교했다. 만족→재방문의 부호가 바뀐다. 좋은 결과가 나오는 방법을 골라주지 말고 점수 구성, 단순/부분 관계, 문항 의미를 확인할 순서를 제안해줘. 역문항 정보가 없는 항목을 임의로 반전시키지 마.”

AI를 썼다면 질문, 제안받은 코드, 직접 확인한 결과, 수정한 해석을 따로 기록합니다. AI를 사용할 수 없는 날에도 제공된 코드와 설명으로 실습을 마칠 수 있습니다.

## 제출할 분석 기록

문항 감사표, 설명영역·결과영역 적재표, 세 점수 방식의 상관/계수 비교, 음의 계수에 대한 가능한 설명과 아직 확인하지 못한 조건을 제출합니다. “유의하니 매장 이전” 같은 실행 불가능한 제안 대신 운영자가 실제 바꿀 수 있는 항목을 제안합니다.

보고서 틀에 질문→자료→방법→근거→실행/보류 판단을 본인 말로 연결합니다. 공식 제출은 집현캠퍼스 안내를 따릅니다. 이 패키지에는 마감일이나 배점을 임의로 설정하지 않았습니다.

## 스스로 확인

음수를 없애려고 자료를 바꾸지 않았는가? 34와 44문항의 차이를 확인했는가?

질문과 방법이 맞는가, 값과 단위가 맞는가, 해석에 한계가 들어 있는가, 실제로 실행할 수 있는 제안인가, 다른 사람이 재실행할 수 있는가를 점검합니다.

## 막혔을 때

- 파일을 못 찾으면 getwd()와 list.files("data")를 확인합니다. ZIP 안에서 직접 실행하지 않습니다.
- 한글 열 이름이 다르면 원본 파일과 UTF-8 인코딩을 확인합니다. 자동으로 열 이름을 고쳐 다른 변수를 분석하지 않습니다.
- stopifnot 오류가 나면 행 수·열 이름·결측치부터 확인합니다. 검사를 지워서 통과시키지 않습니다.
- 수치가 다르면 data 파일, 선택한 그룹, 난수 시드, 패키지 버전을 먼저 대조합니다.
- Quarto는 선택한 폴더의 report-template.qmd를 렌더링합니다. HTML 생성과 R 분석 실행을 각각 확인합니다.
