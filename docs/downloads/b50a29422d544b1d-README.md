# 6장 LAB · 식사금액으로 팁을 설명하되, 예측의 한계까지 읽기

팁이 큰 테이블은 식사금액이 컸기 때문일까요, 인원이 많았기 때문일까요? “식사금액이 1달러 늘면”이라는 문장에 어떤 조건이 붙는지, 예측을 얼마나 믿을 수 있는지 배웁니다.

## 교재와 연결

[회귀분석: 통계의 꽃](https://kwangminpark.github.io/businessAnalytics/Chapter6.html) — 6.1~6.9 계수·더미·적합도·진단, 6.10 tips 종합실습과 이분산 과제

선수학습: 3~5장: 평균 비교와 가정

권장 시간: 기본 110분 + 심화 30분 (수업 운영에 따라 조절)

## 이번 실습에서 배울 것

- 단순 연관성과 다른 변수를 고려한 회귀계수를 구별한다.
- 기준범주·수정 R제곱·잔차 진단을 읽는다.
- 이분산이 있을 때 계수와 표준오차의 역할을 구분한다.

## 먼저 읽을 데이터

tips.csv는 교재 6.10의 reshape2::tips 244건을 고정된 원본에서 CSV로 내보낸 자료입니다. R 기본 datasets에 포함된 자료는 아닙니다. 한 행은 식사 계산서 기록이며 total_bill·tip은 달러, size는 동석 인원, day는 요일, time은 점심/저녁, sex·smoker는 기록된 범주입니다. 동일한 상황/관측자의 기록에 따른 한계가 있어 모든 국가·식당의 팁 행동으로 일반화하지 않습니다. 성별 같은 속성의 계수를 사람의 본질이나 서비스 배분 근거로 해석하지 않습니다.

## 준비와 실행

ZIP을 새 폴더에 풉니다. analysis.R와 data 폴더를 같은 위치에 두고, RStudio 프로젝트 또는 VS Code의 작업 폴더를 이 위치로 엽니다. 먼저 질문에 대한 예상을 쓰고 analysis.R의 번호별 구간을 차례로 실행하세요. 전체 재실행은 `Rscript --vanilla analysis.R`입니다. 원본 data를 덮어쓰지 않습니다. 결과는 output 폴더에 생성됩니다.

reference-output은 검산용입니다. 먼저 자신의 output을 만들고 숫자와 표본 수를 대조하세요. 그림의 글꼴·픽셀은 운영체제에 따라 달라질 수 있습니다.

## 기본 실습 1 · 질문과 단위를 먼저 기록

산점도와 요약을 보고 단순모형 tip~total_bill을 생각합니다. 이번 종속변수는 팁 비율이 아니라 팁 금액입니다. tips를 읽은 뒤 day의 기준을 Sun으로 지정했는지 확인합니다.

## 기본 실습 2 · 교재 모형의 계수 읽기

tip~total_bill+size+day의 계수표를 읽습니다. total_bill 계수는 인원수와 요일이 같다고 놓았을 때의 조건부 연관성입니다. daySat 계수는 같은 금액·인원의 Sun과 비교한 차이입니다. 절편은 자료에서 현실적인 조건인지 따져 봅니다.

## 기본 실습 3 · 변수를 더 넣으면 무조건 좋아질까

sex+smoker+time을 추가한 모형의 R제곱과 수정 R제곱을 비교합니다. R제곱이 조금 커졌다는 이유만으로 좋은 모형이라고 결론 내리지 않습니다. 더미열 VIF도 확인하되 개별 더미의 지표이며 요일 전체의 일반화 VIF와 같지 않음을 구별합니다.

## 기본 실습 4 · 장말 과제: 이분산에 대응

잔차 그림에서 예측값에 따라 흩어짐이 달라지는지 봅니다. hc3.csv에서 보통 표준오차와 HC3 표준오차를 비교합니다. HC3는 오차 크기가 일정하지 않을 때 추론의 민감도를 살피는 방법입니다. 계수를 바꾸거나 빠진 변수, 비선형 관계, 인과 문제를 해결해 주는 버튼은 아닙니다.

## 멈추고 해석하기

교재 모형의 total_bill 계수는 약 0.093, size는 약 0.187입니다. “다른 조건이 같을 때 식사금액 1달러 차이는 평균 팁 약 0.093달러 차이와 연결된다”처럼 씁니다. 기본 종합모형 R²≈0.4691, 수정 R²≈0.4580이며 변수를 더 넣으면 R²≈0.4701이지만 수정 R²≈0.4520입니다. 새 고객에 대한 예측 정확도가 좋아졌다고 확인한 것은 아닙니다.

## AI와 함께 확인하기

“tip~total_bill+size+day에서 Sun을 기준으로 했다. total_bill 계수를 조건부 연관성으로 설명하고, HC3 표준오차와 계수의 차이를 알려줘. 높은 R²나 낮은 p값만으로 인과·예측 성능을 주장하지 마.” 실제 계수표와 다른 수치를 쓰면 원자료 없이 추정했는지 확인합니다.

AI를 썼다면 질문, 제안받은 코드, 직접 확인한 결과, 수정한 해석을 따로 기록합니다. AI를 사용할 수 없는 날에도 제공된 코드와 설명으로 실습을 마칠 수 있습니다.

## 제출할 분석 기록

질문과 모형식, 기준범주, 계수 2개의 문장 해석, 잔차 진단, HC3 비교에서 달라진 판단을 보고합니다. “팁이 적은 직원의 서비스가 나쁘다”처럼 자료가 지지하지 않는 평가를 피합니다.

보고서 틀에 질문→자료→방법→근거→실행/보류 판단을 본인 말로 연결합니다. 공식 제출은 집현캠퍼스 안내를 따릅니다. 이 패키지에는 마감일이나 배점을 임의로 설정하지 않았습니다.

## 스스로 확인

팁 금액과 팁 비율을 구별했는가? 표준오차 수정이 인과효과를 만들어주지 않음을 설명했는가?

질문과 방법이 맞는가, 값과 단위가 맞는가, 해석에 한계가 들어 있는가, 실제로 실행할 수 있는 제안인가, 다른 사람이 재실행할 수 있는가를 점검합니다.

## 막혔을 때

- 파일을 못 찾으면 getwd()와 list.files("data")를 확인합니다. ZIP 안에서 직접 실행하지 않습니다.
- 한글 열 이름이 다르면 원본 파일과 UTF-8 인코딩을 확인합니다. 자동으로 열 이름을 고쳐 다른 변수를 분석하지 않습니다.
- stopifnot 오류가 나면 행 수·열 이름·결측치부터 확인합니다. 검사를 지워서 통과시키지 않습니다.
- 수치가 다르면 data 파일, 선택한 그룹, 난수 시드, 패키지 버전을 먼저 대조합니다.
- Quarto는 선택한 폴더의 report-template.qmd를 렌더링합니다. HTML 생성과 R 분석 실행을 각각 확인합니다.
