# 4장 LAB · 세 브랜드의 매출 차이를 한 장으로 설명하기

같은 지역에 있는 세 커피 브랜드의 일매출이 다릅니다. 본사 회의에서 “어디가 얼마나 다른지”와 “이 결과로 무엇을 할 수 있는지”를 구분해 설명해야 합니다.

## 교재와 연결

[일원배치 분산분석](https://kwangminpark.github.io/businessAnalytics/Chapter4.html) — 4.1 분포, 4.2 ANOVA, 4.3 Tukey, 4.4 브랜드 매출 종합실습

선수학습: 3장: 분포·평균 비교·신뢰구간

권장 시간: 기본 90분 + 심화 30분 (수업 운영에 따라 조절)

## 이번 실습에서 배울 것

- 세 집단 비교에서 ANOVA가 필요한 이유를 설명한다.
- 전체 F검정과 Tukey 쌍별 비교가 답하는 질문을 구분한다.
- 매출 차이를 표·그림·비전공자용 문장으로 전달한다.

## 먼저 읽을 데이터

ch4_data.csv는 교재 4.4 원본 교육자료로 3브랜드×30일=90행입니다. 한 행은 브랜드별 하루 기록입니다. 날짜, 브랜드, 일매출(원), 방문객수(명), 구매고객수(명), 평균체류시간_분이 있습니다. 같은 매장의 날짜별 반복이거나 같은 날의 공동 영향을 받을 수 있으므로 90개 독립 매장의 표본이라고 부르면 안 됩니다. 등장하는 브랜드 이름은 실제 기업의 실측 성과를 보증하지 않습니다.

## 준비와 실행

ZIP을 새 폴더에 풉니다. analysis.R와 data 폴더를 같은 위치에 두고, RStudio 프로젝트 또는 VS Code의 작업 폴더를 이 위치로 엽니다. 먼저 질문에 대한 예상을 쓰고 analysis.R의 번호별 구간을 차례로 실행하세요. 전체 재실행은 `Rscript --vanilla analysis.R`입니다. 원본 data를 덮어쓰지 않습니다. 결과는 output 폴더에 생성됩니다.

reference-output은 검산용입니다. 먼저 자신의 output을 만들고 숫자와 표본 수를 대조하세요. 그림의 글꼴·픽셀은 운영체제에 따라 달라질 수 있습니다.

## 기본 실습 1 · 브랜드별 n과 분포

날짜별 행 수와 브랜드별 행 수를 확인한 뒤 평균·중앙값·산포를 구합니다. 분석 질문은 세 브랜드 평균이 모두 같은가이며, 모든 쌍이 다르다는 가설을 처음부터 정답으로 두지 않습니다.

## 기본 실습 2 · ANOVA 표 읽기

sales~brand 모형의 자유도, 집단 간/집단 내 변동, F값, p값을 짚습니다. F는 집단 간 차이가 집단 안의 흔들림에 비해 얼마나 큰지 비교합니다. F가 크다고 다음 달 매출을 정확히 예측하는 것은 아닙니다.

## 기본 실습 3 · 어디가 다른지 확인

Tukey 표의 comparison은 뒤 집단을 앞 집단에서 뺀 방향으로 읽습니다. diff, lwr, upr, p adj를 함께 기록합니다. 여러 쌍을 비교하므로 보정된 구간과 p값을 사용합니다. p adj가 출력상 0처럼 보이면 매우 작은 값으로 표현합니다.

## 기본 실습 4 · 가정과 전달력 점검

잔차-적합값 그림과 Q-Q 그림을 읽고 Welch ANOVA도 비교합니다. Welch는 등분산 가정에 대한 대안이지 날짜별 의존성의 해결책은 아닙니다. 비전공자에게 세 문장으로 “관측 차이—남는 불확실성—다음 행동”을 설명하는 보고서를 만듭니다.

## 멈추고 해석하기

교재와 같이 스타벅스−메가커피의 평균 일매출 차이는 약 491,322원, 컴포즈커피−메가커피는 약 −276,266원입니다. ANOVA가 유의하더라도 브랜드 이름 자체가 매출 차이의 원인이라고 말할 수 없습니다. 입지·영업시간·규모·날짜 효과가 빠져 있습니다. 계산을 재현하는 것과 브랜드 전체로 일반화하는 것은 별도입니다.

## AI와 함께 확인하기

“세 브랜드의 일별 30개 기록으로 ANOVA와 Tukey를 계산했다. 점장에게 설명할 세 문장을 검토해줘. 여러 날짜가 같은 매장에 속할 수 있고, 실측 시장자료가 아닌 교육자료다. 브랜드 인과효과로 확대하지 말고 차이의 방향을 확인해줘.”

AI를 썼다면 질문, 제안받은 코드, 직접 확인한 결과, 수정한 해석을 따로 기록합니다. AI를 사용할 수 없는 날에도 제공된 코드와 설명으로 실습을 마칠 수 있습니다.

## 제출할 분석 기록

ANOVA 전체 질문, Tukey에서 고른 두 비교, 분포/잔차 그림, 3문장 경영 요약을 제출합니다. 같은 자료의 관측 의존성을 어떻게 추가 확인할지도 한 문장으로 적습니다.

보고서 틀에 질문→자료→방법→근거→실행/보류 판단을 본인 말로 연결합니다. 공식 제출은 집현캠퍼스 안내를 따릅니다. 이 패키지에는 마감일이나 배점을 임의로 설정하지 않았습니다.

## 스스로 확인

ANOVA가 유의하다는 것과 모든 쌍의 차이를 구별했는가? 90행을 90개 매장이라고 하지 않았는가?

질문과 방법이 맞는가, 값과 단위가 맞는가, 해석에 한계가 들어 있는가, 실제로 실행할 수 있는 제안인가, 다른 사람이 재실행할 수 있는가를 점검합니다.

## 막혔을 때

- 파일을 못 찾으면 getwd()와 list.files("data")를 확인합니다. ZIP 안에서 직접 실행하지 않습니다.
- 한글 열 이름이 다르면 원본 파일과 UTF-8 인코딩을 확인합니다. 자동으로 열 이름을 고쳐 다른 변수를 분석하지 않습니다.
- stopifnot 오류가 나면 행 수·열 이름·결측치부터 확인합니다. 검사를 지워서 통과시키지 않습니다.
- 수치가 다르면 data 파일, 선택한 그룹, 난수 시드, 패키지 버전을 먼저 대조합니다.
- Quarto는 선택한 폴더의 report-template.qmd를 렌더링합니다. HTML 생성과 R 분석 실행을 각각 확인합니다.
