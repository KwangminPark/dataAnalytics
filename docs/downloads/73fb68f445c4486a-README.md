# 8장 LAB · 12개 문항을 줄일 때 무엇을 남기고 잃을까?

12개 만족도 항목을 네 개 숫자로 줄이면 보고서는 간결해집니다. 그런데 설명력이 94%라는 이유만으로 남은 정보가 쓸모없다고 할 수 있을까요? 이번 장은 압축의 이득과 잃는 내용을 함께 읽습니다.

## 교재와 연결

[차원축소와 주성분 분석](https://kwangminpark.github.io/businessAnalytics/Chapter8.html) — 8.1 상관, 8.2~8.4 PCA·설명력·가중치, 8.5 적합성, 8.6 정보 손실

선수학습: 2~3장 변수·표준화·분산, 6장 해석과 한계

권장 시간: 기본 100분 + 심화 30분 (수업 운영에 따라 조절)

## 이번 실습에서 배울 것

- 표준화·상관행렬·주성분·누적설명력을 연결한다.
- 주성분 가중치의 크기와 부호를 문항 내용으로 해석한다.
- 차원축소와 잠재요인 탐색의 목적 차이를 설명한다.

## 먼저 읽을 데이터

data.zip의 ch7_data1.csv가 실제로 교재 8장에서 사용하는 300행×12열(Q1~Q12) 자료입니다. 파일 이름의 7 때문에 7장 광고자료로 오인하지 마세요. 본문은 1~5 설문으로 설명하지만 실제 파일은 음수와 소수를 포함한 평균 0 부근의 연속값입니다. 예를 들어 Q1 최소값은 약 −3.30입니다. 원척도와 변환 과정이 별도 확인되지 않았으므로 “1점 미만 응답을 삭제”하거나 실제 응답척도로 해석하지 않습니다. 문항 의미는 Q1~3 응대, Q4~6 음식, Q7~9 환경, Q10 가격·Q11 메뉴·Q12 전반 만족입니다. 공개 SD·rotation 표도 비교용 CSV로 제공합니다.

## 준비와 실행

전체 ZIP을 새 폴더에 풀고 report-template.qmd를 엽니다. 문서 안의 번호별 R 청크를 순서대로 실행합니다. 분석 코드와 판단·해석 작성란은 QMD에서 수정합니다. `quarto render report-template.qmd --to html`로 보고서를 생성합니다. 원본 data를 덮어쓰지 않고 계산 결과는 output에 저장됩니다.

`psych`와 `GPArotation`이 필요합니다. 처음 한 번 R에서 `install.packages(c("psych", "GPArotation"))`를 실행하세요. 패키지를 설치하려면 인터넷이 필요합니다. 데이터 분석 자체에는 인터넷이나 AI 접속이 필요하지 않습니다.

## Quarto 학생 분석 보고서

학생용 report-template.qmd와 교수자 예시 reference-report.qmd는 제공된 Quarto 학생 리포트 템플릿을 기반으로 합니다. 첫 페이지는 결론·권고·핵심 근거·실무적 의미·한계, 본문은 질문→자료→번호별 분석→해석→진단·민감도→결론 순서입니다. 학생용에는 해석 작성란, 교수자용에는 실행값을 반영한 예시 해석이 있습니다.

처음 한 번 install.packages(c("knitr", "rmarkdown"))로 패키지를 준비합니다. ZIP을 풀고 같은 폴더에서 `quarto render report-template.qmd --to html`을 실행하면 QMD 안의 번호별 R 청크를 실행해 표·그림을 생성합니다. 분석 코드와 학생 작성란은 QMD에서 수정합니다. 핵심 근거 선택·모형 선택·판단·해석은 학생이 작성하며 첫 페이지도 분석을 마친 뒤 직접 채웁니다. 별도 analysis.R 없이 실행할 수 있습니다. 캐시와 freeze를 사용하지 않습니다. 기본 R 중심의 분석으로 tidyverse와 broom은 필요하지 않습니다.

Word: `quarto render report-template.qmd --to docx`. PDF: `quarto render report-template.qmd --to pdf` (한국어 LaTeX 필요). styles.css·pagebreak.lua·reference.docx는 원본 템플릿 그대로 ZIP에 포함되어 있습니다. QMD 파일만 다운로드하면 이 보조파일과 데이터가 빠지므로 전체 ZIP을 사용하세요.

reference-output은 검산용입니다. 먼저 자신의 output을 만들고 숫자와 표본 수를 대조하세요. 그림의 글꼴·픽셀은 운영체제에 따라 달라질 수 있습니다.

## 기본 실습 1 · 분석 전에 척도 감사

scale-audit.csv의 범위·평균·표준편차를 확인해 본문 설명과 실제 값의 차이를 적습니다. ID 같은 식별자가 포함되지 않았는지도 봅니다. 상관행렬에서 함께 움직이는 문항을 찾되 응답자가 같은 이유로 답했다고 단정하지 않습니다.

## 기본 실습 2 · 표준화 PCA 실행

prcomp(x, center=TRUE, scale.=TRUE)를 실행합니다. sdev²가 고유값이며 전체 고유값 합으로 나누면 분산 비율입니다. 고유값·비율·누적 비율을 직접 연결해 2개와 4개 축을 남길 때의 차이를 씁니다. 고유값 1은 표준화 기준의 참고 규칙이지 유일한 정답이 아닙니다.

## 기본 실습 3 · 축에 이름 붙이기

PC2에서 음식 문항 Q4~6과 환경 문항 Q7~9가 반대 부호임을 확인합니다. “음식 품질이 좋으면 환경이 나빠진다”는 인과관계가 아니라 이 표본에서 축이 표현하는 대비입니다. rotation은 축의 가중치이고 변수와 주성분의 상관은 rotation×sdev임을 두 출력으로 비교합니다.

## 기본 실습 4 · KMO와 Bartlett 읽기

KMO와 Bartlett은 문항 간 상관구조를 점검하는 참고자료입니다. 유의한 Bartlett이 네 개 축의 경영적 의미까지 검증하지는 않습니다. PCA의 목적은 분산을 보존하는 압축이고, 보이지 않는 공통 원인을 탐색하는 요인분석은 9장에서 구별해 다룹니다.

## 멈추고 해석하기

방법 선택 이유, 결과의 조건·단위, 진단에 따른 판단 변경, 결론의 적용 범위와 한계를 자신의 말로 쓰세요.

## AI와 함께 확인하기

“12문항 PCA의 rotation과 누적설명력을 주겠다. PC 번호만으로 서비스·음식 이름을 붙이지 말고 어떤 문항이 어떤 부호로 기여하는지 설명해줘. rotation 가중치와 변수-PC 상관을 구분하고, 설명력과 경영 중요도를 동일시하지 마.”

AI를 썼다면 질문, 제안받은 코드, 직접 확인한 결과, 수정한 해석을 따로 기록합니다. AI를 사용할 수 없는 날에도 제공된 코드와 설명으로 실습을 마칠 수 있습니다.

## 스스로 확인

원자료의 음수를 임의 삭제하지 않았는가? 설명력을 중요도라고 부르지 않았는가?

질문과 방법이 맞는가, 값과 단위가 맞는가, 해석에 한계가 들어 있는가, 실제로 실행할 수 있는 제안인가, 다른 사람이 재실행할 수 있는가를 점검합니다.

## 막혔을 때

- 파일을 못 찾으면 getwd()와 list.files("data")를 확인합니다. ZIP 안에서 직접 실행하지 않습니다.
- 한글 열 이름이 다르면 원본 파일과 UTF-8 인코딩을 확인합니다. 자동으로 열 이름을 고쳐 다른 변수를 분석하지 않습니다.
- stopifnot 오류가 나면 행 수·열 이름·결측치부터 확인합니다. 검사를 지워서 통과시키지 않습니다.
- 수치가 다르면 data 파일, 선택한 그룹, 난수 시드, 패키지 버전을 먼저 대조합니다.
- Quarto는 선택한 폴더의 report-template.qmd를 렌더링합니다. HTML 생성과 R 분석 실행을 각각 확인합니다.
