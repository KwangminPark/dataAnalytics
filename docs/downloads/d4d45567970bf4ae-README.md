# 2장 LAB · 숫자로 저장됐다고 모두 수량일까?

AI에게 “이 자료를 분석해줘”라고 하면 숫자 열마다 평균을 낼 수 있습니다. 매장 ID나 변속기 코드의 평균도 경영적으로 의미가 있을까요? 이번에는 분석 방법을 고르기 전에 변수의 의미, 관측 단위, 표본 범위를 사람이 먼저 정합니다.

## 교재와 연결

[통계학의 본질과 변수의 이해](https://kwangminpark.github.io/businessAnalytics/Chapter2.html) — 2.1~2.7 통계적 판단과 변수, 2.8.3~2.8.8 장말 실습 전체

선수학습: 1장: 실행 환경과 분석 질문

권장 시간: 기본 90분 + 심화 25분 (수업 운영에 따라 조절)

## 이번 실습에서 배울 것

- 측정 수준과 R 자료형의 차이를 사례로 설명한다.
- 빈도·비율과 평균·표준편차를 질문에 맞게 고른다.
- 작은 p값, 큰 효과, 모집단으로의 일반화를 구분한다.

## 먼저 읽을 데이터

첫 자료 mtcars.csv는 R datasets::mtcars를 내보낸 32개 자동차 자료입니다. car는 차종 이름, mpg는 연비(miles/gallon), cyl은 실린더 수, hp는 마력, am은 변속기 코드(0 자동, 1 수동), gear는 기어 수입니다. cyl과 gear는 수량으로도 정의할 수 있지만 이번 집단 비교에서는 범주로 사용합니다. factor로 바꾸는 이유는 “숫자이므로 틀려서”가 아니라 현재의 분석 질문 때문입니다. 두 번째 ch2_data.csv는 교수 제공 원본 500행의 가상 외식자료입니다. store_id는 식별자, location은 지역, avg_spend는 1인 평균 지출(원), visit_time은 평균 체류시간(분), membership은 일반/VIP, satisfaction은 1~5 만족도입니다. 파일의 행이 어떤 방식으로 추출된 매장/고객을 대표하는지는 생성 설명만으로 확정할 수 없습니다.

## 준비와 실행

ZIP을 새 폴더에 풉니다. analysis.R와 data 폴더를 같은 위치에 두고, RStudio 프로젝트 또는 VS Code의 작업 폴더를 이 위치로 엽니다. 먼저 질문에 대한 예상을 쓰고 analysis.R의 번호별 구간을 차례로 실행하세요. 전체 재실행은 `Rscript --vanilla analysis.R`입니다. 원본 data를 덮어쓰지 않습니다. 결과는 output 폴더에 생성됩니다.

reference-output은 검산용입니다. 먼저 자신의 output을 만들고 숫자와 표본 수를 대조하세요. 그림의 글꼴·픽셀은 운영체제에 따라 달라질 수 있습니다.

## 기본 실습 1 · 변수 사전 만들기

mtcars에서 mpg, cyl, hp, am, gear의 뜻·측정 수준·현재 R 자료형·사용할 요약을 네 열의 표로 씁니다. am의 0과 1이 크기 순서가 아닌 이유를 설명합니다. cyl을 집단으로 묶을 때와 엔진 크기의 수치로 다룰 때 질문이 어떻게 다른지 비교하세요.

## 기본 실습 2 · 원문의 자동차 실습 재현하기

analysis.R의 1단계를 실행합니다. 변속기는 빈도와 비율로, 연비는 실린더 집단별 평균과 표준편차로 요약합니다. mpg-by-cyl.csv와 그림을 읽으며 표본 수가 다른지도 확인합니다. aov 출력은 이 장에서는 p값을 읽는 연습으로만 사용합니다. 분산분석의 구조와 사후검정은 4장에서 배웁니다.

## 기본 실습 3 · 외식자료로 옮겨보기

2단계를 실행하기 전에 store_id의 평균, location의 평균, avg_spend의 평균 중 어떤 것이 의미 있는지 고릅니다. 지역별 지출과 회원유형별 만족도 분포를 비교하고, 체류시간과 지출의 산점도를 봅니다. 만족도 한 문항은 순서형이라는 점을 기억하고 빈도표를 먼저 확인합니다. 평균을 사용할 경우 점수 간 간격을 같게 취급한다는 가정을 적으세요.

## 기본 실습 4 · 표본에서 모집단으로 넘어가는 문장 고치기

“VIP 만족도가 더 높으니 VIP 가입이 만족을 올린다”를 고쳐 씁니다. 실제로 높게 나왔는지부터 표에서 확인합니다. 높은 경우에도 원래 만족도가 높은 사람이 가입했을 가능성을 생각합니다. 지역 ANOVA의 p값이 작더라도 모든 지역 쌍이 다르다는 뜻은 아닙니다. 모집단, 표본 추출, 가상자료 여부가 빠진 결론을 표시하세요.

## 멈추고 해석하기

자동차 자료에서 자동변속기는 19개, 수동은 13개입니다. 4·6·8실린더 집단의 평균 연비는 약 26.66, 19.74, 15.10입니다. 이 차이는 표본의 특성을 설명하며 무작위 실험의 인과효과가 아닙니다. p값은 귀무가설과 분석 가정 아래 관측 결과만큼 또는 더 극단적인 결과가 나올 확률입니다. “귀무가설이 참일 확률”이나 “효과의 크기”가 아닙니다. R의 c()는 값을 결합하는 함수이며 column의 약어로 해석하지 않습니다.

## AI와 함께 확인하기

“ch2_data.csv의 변수 사전을 내가 먼저 작성했다. store_id는 ID, location과 membership은 명목형, satisfaction은 순서형으로 보았다. 이 판단과 요약방법이 맞는지 검토해줘. R 자료형과 측정 수준을 구분하고, 관측자료에서 인과효과를 단정하지 마.” AI가 사실상 데이터에 없는 조사 설계를 덧붙이지 않았는지 확인합니다.

AI를 썼다면 질문, 제안받은 코드, 직접 확인한 결과, 수정한 해석을 따로 기록합니다. AI를 사용할 수 없는 날에도 제공된 코드와 설명으로 실습을 마칠 수 있습니다.

## 제출할 분석 기록

두 데이터의 변수 사전, mtcars 재현 표, 외식자료에 대한 질문 2개와 근거 표/그림, AI의 해석에서 수정한 문장 1개를 제출합니다. 검정 이름을 많이 나열하는 것보다 변수와 질문이 맞는지를 설명하는 것이 중요합니다.

보고서 틀에 질문→자료→방법→근거→실행/보류 판단을 본인 말로 연결합니다. 공식 제출은 집현캠퍼스 안내를 따릅니다. 이 패키지에는 마감일이나 배점을 임의로 설정하지 않았습니다.

## 스스로 확인

ID를 평균내지 않았는가? factor 변환의 이유를 분석 질문으로 설명했는가?

질문과 방법이 맞는가, 값과 단위가 맞는가, 해석에 한계가 들어 있는가, 실제로 실행할 수 있는 제안인가, 다른 사람이 재실행할 수 있는가를 점검합니다.

## 막혔을 때

- 파일을 못 찾으면 getwd()와 list.files("data")를 확인합니다. ZIP 안에서 직접 실행하지 않습니다.
- 한글 열 이름이 다르면 원본 파일과 UTF-8 인코딩을 확인합니다. 자동으로 열 이름을 고쳐 다른 변수를 분석하지 않습니다.
- stopifnot 오류가 나면 행 수·열 이름·결측치부터 확인합니다. 검사를 지워서 통과시키지 않습니다.
- 수치가 다르면 data 파일, 선택한 그룹, 난수 시드, 패키지 버전을 먼저 대조합니다.
- Quarto는 선택한 폴더의 report-template.qmd를 렌더링합니다. HTML 생성과 R 분석 실행을 각각 확인합니다.
