# 1장 LAB · 감으로 정한 인력 배치, 어떤 질문부터 할까?

토요일에 손님이 더 많다는 이유로 직원을 늘려도 될까요? 매장 책임자는 인력 배치를 정해야 하지만, 분석가는 아직 비용과 대기시간 자료를 받지 못했습니다. 이때 할 일은 어려운 분석을 고르는 것이 아니라 판단에 필요한 질문을 만드는 일입니다.

## 교재와 연결

[오리엔테이션](https://kwangminpark.github.io/businessAnalytics/Chapter1.html) — 1.1~1.3 분석가의 역할, 1.4 실습 환경과 Quarto

선수학습: 없음. 통계검정이나 회귀분석을 먼저 알 필요가 없습니다.

권장 시간: 기본 60분 + 심화 20분 (수업 운영에 따라 조절)

## 이번 실습에서 배울 것

- 막연한 요청을 결정할 일·비교할 대상·필요한 자료로 나누어 쓴다.
- 방문객 수, 구매 비율, 구매고객당 매출을 구별한다.
- R로 표와 그림을 만들고 Quarto 보고서로 자신의 판단을 전달한다.

## 먼저 읽을 데이터

decision-example.csv는 교재 1.1의 인력 배치 상황을 연습하기 위해 새로 구성한 2행의 설명용 장부입니다. 실제 관측자료도, 교재에 있던 원본 표도 아닙니다. 한 행은 한 요일의 하루를 뜻합니다. Friday/Saturday는 금요일/토요일, visitors는 방문객 수(명), buyers는 구매고객 수(명), sales는 매출(원), labor_hours는 투입 근로시간(시간)입니다. 이 두 날로 다음 달의 수요를 추론하지 않습니다. 비용, 이익, 기다린 시간, 서비스를 포기한 사람 수는 없습니다.

## 준비와 실행

전체 ZIP을 새 폴더에 풀고 report-template.qmd를 엽니다. 문서 안의 번호별 R 청크를 순서대로 실행합니다. 분석 코드와 판단·해석 작성란은 QMD에서 수정합니다. `quarto render report-template.qmd --to html`로 보고서를 생성합니다. 원본 data를 덮어쓰지 않고 계산 결과는 output에 저장됩니다.

## Quarto 학생 분석 보고서

학생용 report-template.qmd와 교수자 예시 reference-report.qmd는 제공된 Quarto 학생 리포트 템플릿을 기반으로 합니다. 첫 페이지는 결론·권고·핵심 근거·실무적 의미·한계, 본문은 질문→자료→번호별 분석→해석→진단·민감도→결론 순서입니다. 학생용에는 해석 작성란, 교수자용에는 실행값을 반영한 예시 해석이 있습니다.

처음 한 번 install.packages(c("knitr", "rmarkdown"))로 패키지를 준비합니다. ZIP을 풀고 같은 폴더에서 `quarto render report-template.qmd --to html`을 실행하면 QMD 안의 번호별 R 청크를 실행해 표·그림을 생성합니다. 분석 코드와 학생 작성란은 QMD에서 수정합니다. 핵심 근거 선택·모형 선택·판단·해석은 학생이 작성하며 첫 페이지도 분석을 마친 뒤 직접 채웁니다. 별도 analysis.R 없이 실행할 수 있습니다. 캐시와 freeze를 사용하지 않습니다. 기본 R 중심의 분석으로 tidyverse와 broom은 필요하지 않습니다.

Word: `quarto render report-template.qmd --to docx`. PDF: `quarto render report-template.qmd --to pdf` (한국어 LaTeX 필요). styles.css·pagebreak.lua·reference.docx는 원본 템플릿 그대로 ZIP에 포함되어 있습니다. QMD 파일만 다운로드하면 이 보조파일과 데이터가 빠지므로 전체 ZIP을 사용하세요.

reference-output은 검산용입니다. 먼저 자신의 output을 만들고 숫자와 표본 수를 대조하세요. 그림의 글꼴·픽셀은 운영체제에 따라 달라질 수 있습니다.

## 기본 실습 1 · 결정과 예상 쓰기

코드를 실행하기 전에 “토요일에 직원을 더 배치한다”에 찬성·보류 중 하나를 선택하고 이유를 한 문장으로 씁니다. 그런 다음 “방문객 수가 많다”와 “직원이 부족하다”가 같은 뜻인지 설명합니다. 어떤 사실을 더 알아야 마음을 바꿀지도 적습니다.

## 기본 실습 2 · 분모가 있는 지표 만들기

report-template.qmd의 1~2단계를 실행합니다. 구매 비율은 buyers/visitors, 구매고객당 매출은 sales/buyers, 근로시간당 매출은 sales/labor_hours입니다. 각 나눗셈에서 분모를 말로 읽습니다. 구매하지 않은 사람도 포함하는 방문객당 매출과 구매고객당 매출을 혼동하지 마세요.

## 기본 실습 3 · 표와 그래프 확인하기

output/decision-table.csv와 first-chart.png를 엽니다. 금요일보다 토요일의 방문객은 많지만 구매 비율과 근로시간당 매출은 어떤지 확인합니다. 막대그래프의 세로축은 원 단위 매출입니다. 그림 하나로 구매 비율까지 알 수 있는지 점검합니다.

## 기본 실습 4 · 분석 기록을 문서로 만들기

report-template.qmd를 열어 먼저 내린 판단과 표를 본 뒤의 판단을 씁니다. Quarto로 HTML을 렌더링하고 표·그림·출처가 보이는지 확인합니다. R 실행 성공, 그림 생성, 문서 생성은 서로 다른 확인 항목입니다. 마지막으로 report-template.qmd의 나눗셈 한 줄을 본인의 말로 설명합니다.

## 멈추고 해석하기

방법 선택 이유, 결과의 조건·단위, 진단에 따른 판단 변경, 결론의 적용 범위와 한계를 자신의 말로 쓰세요.

## AI와 함께 확인하기

“나는 매장의 주말 인력 배치를 판단하려 한다. 현재 자료는 두 날의 visitors, buyers, sales, labor_hours뿐이다. 각 지표의 분자·분모를 설명하고, 이 자료로 답할 수 없는 질문 세 개를 제안해줘. 적정 직원 수나 인과효과를 만들어내지 마.” AI가 이익을 계산했다면 비용 변수가 실제로 있는지 확인하세요.

AI를 썼다면 질문, 제안받은 코드, 직접 확인한 결과, 수정한 해석을 따로 기록합니다. AI를 사용할 수 없는 날에도 제공된 코드와 설명으로 실습을 마칠 수 있습니다.

## 제출할 분석 기록

결정할 일 1문장, 지표 3개의 계산표, 그림 1개, 보류한 주장 1개, 다음 주에 수집할 항목 3개를 제출용 보고서에 담습니다. 좋은 기록은 “토요일이 나쁘다”보다 “어떤 정보를 더 모으면 인력 배치를 결정할 수 있다”를 분명하게 말합니다.

보고서 틀에 질문→자료→방법→근거→실행/보류 판단을 본인 말로 연결합니다. 공식 제출은 집현캠퍼스 안내를 따릅니다. 이 패키지에는 마감일이나 배점을 임의로 설정하지 않았습니다.

## 스스로 확인

매출이 높은 날이 반드시 이익도 높다는 주장에 답할 수 있는가? 분자와 분모를 정확히 적었는가?

질문과 방법이 맞는가, 값과 단위가 맞는가, 해석에 한계가 들어 있는가, 실제로 실행할 수 있는 제안인가, 다른 사람이 재실행할 수 있는가를 점검합니다.

## 막혔을 때

- 파일을 못 찾으면 getwd()와 list.files("data")를 확인합니다. ZIP 안에서 직접 실행하지 않습니다.
- 한글 열 이름이 다르면 원본 파일과 UTF-8 인코딩을 확인합니다. 자동으로 열 이름을 고쳐 다른 변수를 분석하지 않습니다.
- stopifnot 오류가 나면 행 수·열 이름·결측치부터 확인합니다. 검사를 지워서 통과시키지 않습니다.
- 수치가 다르면 data 파일, 선택한 그룹, 난수 시드, 패키지 버전을 먼저 대조합니다.
- Quarto는 선택한 폴더의 report-template.qmd를 렌더링합니다. HTML 생성과 R 분석 실행을 각각 확인합니다.
