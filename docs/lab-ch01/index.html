먼저 판단할 질문

토요일에 손님이 더 많다는 이유로 직원을 늘려도 될까요? 매장 책임자는 인력 배치를 정해야 하지만, 분석가는 아직 비용과 대기시간 자료를 받지 못했습니다. 이때 할 일은 어려운 분석을 고르는 것이 아니라 판단에 필요한 질문을 만드는 일입니다.

교재에서 실습으로

교재 1장 오리엔테이션 1.1~1.3 분석가의 역할, 1.4 실습 환경과 Quarto 선수학습: 없음. 통계검정이나 회귀분석을 먼저 알 필요가 없습니다. 권장 시간: 기본 60분 + 심화 20분 1. 막연한 요청을 결정할 일·비교할 대상·필요한 자료로 나누어 쓴다. 2. 방문객 수, 구매 비율, 구매고객당 매출을 구별한다. 3. R로 표와 그림을 만들고 Quarto 보고서로 자신의 판단을 전달한다.

자료와 한 행의 의미

decision-example.csv는 교재 1.1의 인력 배치 상황을 연습하기 위해 새로 구성한 2행의 설명용 장부입니다. 실제 관측자료도, 교재에 있던 원본 표도 아닙니다. 한 행은 한 요일의 하루를 뜻합니다. Friday/Saturday는 금요일/토요일, visitors는 방문객 수(명), buyers는 구매고객 수(명), sales는 매출(원), labor_hours는 투입 근로시간(시간)입니다. 이 두 날로 다음 달의 수요를 추론하지 않습니다. 비용, 이익, 기다린 시간, 서비스를 포기한 사람 수는 없습니다.

준비와 실행

아래 실습 ZIP을 새 폴더에 풀고 analysis.R와 data 폴더를 나란히 둡니다. RStudio 프로젝트 또는 VS Code 작업 폴더를 이 위치로 엽니다. 먼저 자신의 예상을 적은 뒤 analysis.R의 번호별 구간을 실행합니다. 전체 재실행: Rscript --vanilla analysis.R. 결과는 output에 저장됩니다. 8·9장은 psych와 GPArotation 패키지가 필요합니다. 처음 한 번 install.packages(c("psych", "GPArotation"))로 설치합니다. 이후 데이터 분석은 인터넷 없이 가능합니다. Quarto 보고서 틀은 실행 결과를 정리하는 문서이며 R 코드는 analysis.R에서 별도로 실행합니다. 기준 출력은 먼저 자신의 결과를 만든 뒤 대조하세요.

기본 실습 1 · 결정과 예상 쓰기

코드를 실행하기 전에 “토요일에 직원을 더 배치한다”에 찬성·보류 중 하나를 선택하고 이유를 한 문장으로 씁니다. 그런 다음 “방문객 수가 많다”와 “직원이 부족하다”가 같은 뜻인지 설명합니다. 어떤 사실을 더 알아야 마음을 바꿀지도 적습니다.

기본 실습 2 · 분모가 있는 지표 만들기

analysis.R의 1~2단계를 실행합니다. 구매 비율은 buyers/visitors, 구매고객당 매출은 sales/buyers, 근로시간당 매출은 sales/labor_hours입니다. 각 나눗셈에서 분모를 말로 읽습니다. 구매하지 않은 사람도 포함하는 방문객당 매출과 구매고객당 매출을 혼동하지 마세요.

기본 실습 3 · 표와 그래프 확인하기

output/decision-table.csv와 first-chart.png를 엽니다. 금요일보다 토요일의 방문객은 많지만 구매 비율과 근로시간당 매출은 어떤지 확인합니다. 막대그래프의 세로축은 원 단위 매출입니다. 그림 하나로 구매 비율까지 알 수 있는지 점검합니다.

기본 실습 4 · 분석 기록을 문서로 만들기

report-template.qmd를 열어 먼저 내린 판단과 표를 본 뒤의 판단을 씁니다. Quarto로 HTML을 렌더링하고 표·그림·출처가 보이는지 확인합니다. R 실행 성공, 그림 생성, 문서 생성은 서로 다른 확인 항목입니다. 마지막으로 analysis.R의 나눗셈 한 줄을 본인의 말로 설명합니다.

# 결과를 output 폴더에 저장합니다. 원본 data 파일은 바꾸지 않습니다.
options(digits=7)
dir.create("output",showWarnings=FALSE)
read_data <- function(name) read.csv(file.path("data",name),fileEncoding="UTF-8-BOM",check.names=FALSE,stringsAsFactors=FALSE)
export <- function(x,name) { print(x); write.csv(x,file.path("output",paste0(name,".csv")),row.names=FALSE) }
coef_table <- function(m) { z <- coef(summary(m)); ci <- confint(m); data.frame(term=rownames(z),estimate=z[,1],se=z[,2],p=z[,4],low=ci[,1],high=ci[,2],row.names=NULL) }
summary_by <- function(x,g) do.call(rbind,lapply(split(x,g),function(y) data.frame(n=length(y),mean=mean(y),median=median(y),sd=sd(y),IQR=IQR(y))))
picture <- function(name,w=1100,h=720) png(file.path("output",paste0(name,".png")),width=w,height=h,res=120)
sink("output/results.txt",split=TRUE)
# 1. 먼저 질문: 사람이 더 필요한 날을 방문객 수만으로 고를 수 있을까?
d <- read_data("decision-example.csv")
stopifnot(nrow(d)==2,all(d$buyers<=d$visitors))
print(d)
# 2. 분자와 분모를 읽으며 계산하기. 이익은 비용자료가 없어 계산할 수 없습니다.

멈추고 해석하기

기준 계산에서 구매 비율은 금요일 90%, 토요일 70%입니다. 구매고객당 매출은 각각 15,000원과 14,000원이고, 근로시간당 매출은 45,000원과 약 32,667원입니다. 그러나 이익이나 적정 직원 수를 구한 것은 아닙니다. 시간당 매출이 낮은 이유가 직원 과다인지, 고객 대기·구매 포기인지 아직 알 수 없습니다. “추가 관측 후 배치를 결정하겠다”도 근거가 있는 경영 판단입니다.

AI와 함께 확인하기

“나는 매장의 주말 인력 배치를 판단하려 한다. 현재 자료는 두 날의 visitors, buyers, sales, labor_hours뿐이다. 각 지표의 분자·분모를 설명하고, 이 자료로 답할 수 없는 질문 세 개를 제안해줘. 적정 직원 수나 인과효과를 만들어내지 마.” AI가 이익을 계산했다면 비용 변수가 실제로 있는지 확인하세요. 질문·제안받은 코드·직접 검증한 결과·수정한 해석을 구분해 기록합니다. AI 접속 없이도 제공된 코드와 설명으로 실습을 마칠 수 있습니다.

제출할 분석 기록

결정할 일 1문장, 지표 3개의 계산표, 그림 1개, 보류한 주장 1개, 다음 주에 수집할 항목 3개를 제출용 보고서에 담습니다. 좋은 기록은 “토요일이 나쁘다”보다 “어떤 정보를 더 모으면 인력 배치를 결정할 수 있다”를 분명하게 말합니다. 질문→자료→방법→근거→실행/보류 판단을 연결합니다. 공식 제출은 집현캠퍼스 안내를 따릅니다. 마감일·배점은 이 자료에서 정하지 않습니다. 스스로 확인: 매출이 높은 날이 반드시 이익도 높다는 주장에 답할 수 있는가? 분자와 분모를 정확히 적었는가?
